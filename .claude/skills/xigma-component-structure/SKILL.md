# xigma Component Structure

## Folder shape

One folder per component, PascalCase, named identically to the default export. The `.tsx`/`.spec.tsx`
files match that PascalCase name, but **the `.module.scss` file is kebab-case** — this is easy to
miss because single-word components (`App.module.scss`) look identical either way, but it's
confirmed unambiguously across every multi-word component in the real codebase: `mouse-modes.module.scss`
(`MouseModes/`), `tool-dropdown.module.scss` (`ToolDropdown/`), `design-page.module.scss`
(`DesignPage/`), `home-page.module.scss`, `not-found-page.module.scss`, `left-panel.module.scss`,
`right-panel.module.scss`, `popover-item.module.scss`, `popover-separator.module.scss`,
`icon.module.scss` (`Icon/`) — every single multi-word `.module.scss` in the tree is kebab-case,
zero exceptions among pre-existing files. Corrected by direct user correction after two components
(`CommentDraftInput/`, `CommentPin/`) were built with PascalCase `.module.scss` filenames instead —
caught by `find src -iname "*.module.scss"` and comparing casing across all of them, not by reading
this doc's own (misleading, single-word) example.

```
components/MouseModes/
  MouseModes.tsx
  mouse-modes.module.scss
  MouseModes.spec.tsx
  snapshots/
    MouseModes.spec.tsx.snap   (generated by Vitest, see vite.config.ts resolveSnapshotPath)
```

Pages under `pages/` follow the exact same shape (`pages/HomePage/HomePage.tsx`, `home-page.module.scss`,
`HomePage.spec.tsx`). See [[xigma-module-structure]] for how `types.ts`/`constants.ts`/`utils/` join
this shape once a component grows beyond a single file.

One pre-existing exception was found and left alone (not in scope to fix unprompted):
`Canvas/components/TextEditOverlay/TextEditOverlay.module.scss` is PascalCase — an existing
inconsistency, not a second valid pattern to follow.

## The component file

```tsx
import { FC } from 'react';

// styles
import styles from './component-name.module.scss';

const ComponentName: FC<TComponentNameProps> = (props) => (
  <div className={styles.ComponentName}>...</div>
);

export default ComponentName;
```

- `FC` from `react`, arrow function, PascalCase matching the folder/file name.
- **Both** a named export (`export const ComponentName`) when other files need the type/reference
  directly, **and always** `export default ComponentName` at the bottom — this is what lets a
  barrel (`shared/index.ts`, `hooks/index.ts`) do `export * from './UITools/Popover/Popover'` and
  still expose a usable named binding. See `shared/UITools/Popover/Popover.tsx` for the named+default
  pair in practice.
- Props type is `TComponentNameProps` (the `T` prefix + PascalCase name convention — see
  `core/Routing/components/ProtectedRoute/ProtectedRoute.tsx`'s `TProtectedRouteProps`).

## Styles: CSS Modules, not global classes

Every component imports its own `.module.scss` and reads classes off the `styles` object —
`className={styles.ComponentName}`. The top-level class inside the file matches the component name
exactly (`.App`, `.Icon`, `.HomePage`), sub-elements get their own PascalCase class
(`.ThemeToggle` in `App.module.scss`). Colors are never hardcoded — always the CSS custom properties
from [[xigma-theming]] (`background-color: var(--color-neutral-4);`), so components repaint
automatically on theme change with zero JS.

When a color is needed as a **prop value** rather than in `.module.scss` (e.g. an inline `style`, or
passed into a child component), pull it from `constant/colors` instead of writing `var(--color-*)`
by hand — see `HomePage.tsx`'s `style={{ color: colors.neutral2 }}`.

## Tests

Co-located `ComponentName.spec.tsx`, not a separate `__tests__` folder — see
[[xigma-test-conventions]] for the `describe`/`it` naming and step-comment convention used inside
it, and [[xigma-import-order]] for how the imports at the top of both the component and its spec
are grouped.
